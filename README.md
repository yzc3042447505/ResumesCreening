# 候选人初筛助手

> AI智能辅助 · 匹配有据可溯 · 决策由人完成

一款基于大语言模型的AI简历初筛工具，专为中小型互联网公司和技术团队招聘设计。通过Agent架构实现JD解析、简历脱敏、智能匹配、面试题生成等功能，帮助招聘人员快速筛选候选人，大幅提升招聘效率。

## 项目解决什么问题

传统简历筛选存在以下痛点：

- **效率低下**：HR手动阅读几十上百份简历，耗时耗力
- **标准不一**：不同招聘者筛选标准不一致，主观性强
- **信息过载**：简历格式各异，关键信息难以快速提取
- **偏见风险**：性别、年龄、婚育等因素可能无意识影响判断
- **缺乏记录**：筛选过程和理由难以追溯和复盘

本项目通过AI技术解决这些问题：

- 自动提取JD和简历的结构化信息
- 逐条对比岗位要求，给出可解释的匹配评分
- 内置脱敏处理，过滤敏感信息，保证筛选公平性
- 自动生成定制化面试题，提升面试准备效率
- 完整的历史记录和人工修正功能，让AI做辅助、人做决策

## 主要功能

### 📄 智能解析
- JD结构化解析（岗位名称、硬性要求、加分项、岗位职责）
- 简历信息智能提取（技能、工作年限、学历、项目经历等）
- 支持 PDF / DOCX / TXT 格式

### 🛡️ 隐私保护与脱敏
- 简历文本预脱敏处理
- 结构化数据二次脱敏校验
- 过滤性别、年龄、婚育、民族、照片等敏感信息
- 符合个人信息保护法要求

### 🎯 AI驱动匹配
- 逐条对比岗位硬性要求
- 每个匹配点附带简历证据溯源
- 加分项匹配评估
- 一票否决项检查
- 总体匹配分（0-100分）+ 自动优先级排序

### ✨ 定制面试题生成
- 针对项目经历深挖题
- 针对能力缺口考察题
- 每题附带考察点和出题理由
- 提供追问方向建议

### ✏️ 人工修正与协作
- 手动调整匹配分数
- 候选人状态标记（待查看/约面/待定/淘汰）
- 添加个人备注
- 按状态筛选候选人

### ⚡ 批量操作
- 批量上传简历
- 批量标记状态
- 批量导出选中候选人
- 全选/反选功能

### 📋 岗位模板库
- 内置常用岗位JD模板（Python后端、前端、产品经理、测试开发）
- 自定义模板管理（新增/编辑/删除）
- 一键选用模板，无需重复上传

### 📝 面试纪要生成
- 五维度评分（技术能力/项目经验/沟通表达/文化匹配/综合印象）
- 优势与顾虑记录
- AI自动生成结构化面试纪要
- 录用建议（强烈推荐/推荐/待定/不推荐）

### 📚 历史记录
- 自动保存筛选结果
- 历史任务随时查看和导出
- SQLite本地数据库存储
- 支持删除单条任务和清空全部历史

### 📤 导出功能
- Excel格式导出候选人对比表
- CSV格式导出
- 包含匹配详情Sheet
- 支持批量导出选中候选人

## 安装方法

### 环境要求
- Python 3.10+
- 大模型API密钥（兼容OpenAI格式的API，如火山方舟、DeepSeek等）

### 安装步骤

1. **克隆项目**
```bash
git clone <你的仓库地址>
cd recruitment-assistant
```

2. **创建虚拟环境**
```bash
python -m venv venv
```

3. **激活虚拟环境**

Windows:
```bash
venv\Scripts\activate
```

Linux/Mac:
```bash
source venv/bin/activate
```

4. **安装依赖**
```bash
pip install -r requirements.txt
```

5. **配置大模型API（重要）**

本项目需要大语言模型API才能运行，**API密钥由使用者自行配置，费用由使用者承担**。

支持任何兼容OpenAI Chat Completions格式的API服务，包括但不限于：
- 火山方舟（豆包大模型）
- DeepSeek
- OpenAI
- 其他兼容OpenAI格式的API服务

**配置方式一：在界面中配置（推荐）**

启动应用后，在左侧边栏顶部的「API配置」区域：
1. 选择你的API服务商
2. 输入你的API Key
3. 确认API Base URL和模型名称
4. 点击「保存配置」

配置信息仅保存在当前浏览器会话中，不会上传到服务器。

**配置方式二：通过.env文件配置**

创建 `.env` 文件并填写：
```bash
# 大模型API地址（兼容OpenAI格式）
LLM_BASE_URL=https://ark.cn-beijing.volces.com/api/v3

# 模型名称或接入点ID
LLM_MODEL=doubao-seed-2.1-pro

# API密钥
LLM_API_KEY=your-api-key

# 单次最大简历数量
MAX_RESUME_COUNT=20
```

## 使用方法

### 启动应用

```bash
python app.py
```

应用会自动在浏览器中打开，默认地址为 `http://localhost:8501`。

### 使用流程

1. **配置API**：首次使用时，在左侧边栏配置你的大模型API密钥（选择服务商、输入API Key、确认模型名称）
2. **上传JD**：上传岗位描述文件（PDF/DOCX/TXT），或从岗位模板库中选择
3. **上传简历**：批量上传候选人简历（支持PDF/DOCX/TXT，建议一次不超过20份）
4. **开始筛选**：点击「开始智能筛选」按钮，等待AI处理
5. **查看结果**：浏览候选人匹配结果，查看匹配证据和面试题
6. **人工修正**：调整分数、标记状态、添加备注
7. **生成纪要**：面试后填写评分，AI自动生成面试纪要
8. **导出数据**：导出候选人对比表（Excel/CSV）

## 设计理念

本项目的核心理念是 **"AI做辅助，人做决策"**：

- AI只负责信息提取、排序建议、面试准备和记录
- 最终录用决定必须由人做出
- 每个分数都能解释来源，确保可追溯
- 不使用性别、年龄、婚育等敏感信息评分
- 提供完整的人工修改和纠正入口

## 注意事项

- 本工具仅辅助招聘决策，不替代人工判断
- 简历包含敏感个人信息，请妥善处理和存储
- 建议在处理完成后及时删除原始简历文件
- **大模型API调用会产生费用，由使用者自行承担**
- API密钥仅保存在当前会话，请勿在公共设备上使用
- 本项目不对API调用的准确性、稳定性、费用做任何担保


## 数据存储模式

本项目支持两种数据存储模式，通过环境变量 `APP_ENV` 控制：

### 本地持久化模式（推荐本地开发使用）

在 `.env` 文件中设置：
```bash
APP_ENV=local
```

- 筛选结果存入 SQLite 数据库（`data/history.db`）
- 数据持久化保存，应用重启后仍然存在
- 历史记录可随时查看和导出
- 适合本地开发和个人使用

### 线上临时模式（部署到服务器时默认）

不设置 `APP_ENV` 环境变量，或设置为其他值：

- 筛选结果仅保存在当前浏览器会话（session_state）中
- 应用重启后数据将被清除
- 当前会话内可正常查看、筛选、导出
- 适合公开部署，保护用户隐私，避免多用户数据混乱

> **注意**：线上模式下，请提醒用户及时导出 Excel 保存数据，应用重启后数据将丢失。

### 如果想让线上历史数据一直存在

如果部署到线上后希望历史数据持久化保存，有两种方案：

1. **设置 APP_ENV=local**：在服务器的环境变量中设置 `APP_ENV=local`，数据将存入服务器本地的 SQLite 数据库。但注意：所有用户共享同一个数据库，能看到彼此的历史记录，适合单用户或内部使用。

2. **接入外部数据库**：将 `utils/database.py` 中的 SQLite 替换为 PostgreSQL/MySQL 等外部数据库，并添加用户系统实现数据隔离。这需要额外的开发工作。
